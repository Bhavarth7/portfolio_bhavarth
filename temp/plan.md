## 6. Visual system

### Direction

Keep the existing midnight navy and teal identity, but evolve from “sci-fi résumé” to “precision AI systems studio.”

- Background: near-black navy with subtle depth, not pure black.
- Primary text: warm off-white with strong contrast.
- Accent: restrained teal for state and success.
- Secondary accent: cool violet or electric blue used only for model/system layers.
- Data/error state: amber or coral, never color alone.
- Typography: one confident grotesk/display face plus a highly readable sans; monospace for metrics and traces.
- Grid: 12-column desktop, 8 tablet, 4 mobile.
- Reading width: approximately 68 characters.

### Signature visual language

- System diagrams.
- Execution traces.
- Evaluation panels.
- Before/after performance plots.
- Architecture layers.
- Decision annotations.

Avoid stock imagery, decorative AI brains, robots, excessive glassmorphism, random 3D objects, and continuous particles.

## 7. Motion system

Motion should demonstrate system behavior.

### Allowed

- A task token traversing an agent workflow.
- State checkpoint and recovery.
- Retrieval documents becoming ranked evidence.
- Latency/cost metrics transitioning between architecture versions.
- Section transitions that reveal hierarchy in 200-500 ms.

### Avoid

- Perpetual particle fields.
- Large text moving while being read.
- Scroll hijacking.
- Custom cursors.
- Long pre-loaders.
- Fake terminal typing that delays access to content.
- Count-up metrics that obscure exact values.

### Performance and accessibility contract

- Animate only `transform` and `opacity` when possible.
- Essential content is visible before JavaScript.
- `prefers-reduced-motion` renders every interaction in its completed static state.
- Do not auto-play animations more than once per session unless user-triggered.
- Keep the hero animation under a small explicit performance budget.
