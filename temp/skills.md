# Portfolio Capability Map

This is the skill-development plan the portfolio should demonstrate. It is not a decorative keyword cloud. Every claimed skill should link to evidence.

## Evidence scale

- **Level 0 — Aware:** can explain the concept.
- **Level 1 — Practiced:** completed a focused exercise or implementation.
- **Level 2 — Applied:** used it in a meaningful project with evaluation.
- **Level 3 — Production:** operated it under real reliability, scale, cost, or user constraints.
- **Level 4 — Authority:** created reusable methods, taught others, or published original insight validated by peers.

On the public site, show only Levels 2–4. Use honest labels such as “Production,” “Applied,” and “Exploring”; never use percentage proficiency bars.

## Twelve-month mastery plan

### Quarter 1 — Evidence and production depth

- Turn the Brand Extraction project into a full production-systems case study.
- Build an evaluation harness: golden set, schema adherence, precision/recall, latency, cost, and regression tests.
- Add tracing, retry policy, failure taxonomy, and operational dashboard.
- Publish one architecture article and one postmortem.

**Proof:** public case study, sanitized code, evaluation report, diagram, and demo video.

### Quarter 2 — ML rigor

- Revisit one forecasting or churn project with stronger baselines.
- Add leakage analysis, calibration, slice-based errors, uncertainty, and drift strategy.
- Document the bridge from model metric to business outcome.
- Reproduce and critique one relevant paper.

**Proof:** reproducible notebook/repository, model card, business metric memo, and article.

### Quarter 3 — Systems and scale

- Design a batch + online inference system with explicit SLOs.
- Benchmark throughput, latency, concurrency, and cost.
- Practice containerization, deployment, observability, rollback, and load testing.
- Write an incident simulation and runbook.

**Proof:** system-design document, benchmark report, operational dashboard, and runbook.

### Quarter 4 — Authority and teaching

- Publish a cohesive five-part series on reliable applied AI.
- Create one open-source reusable tool, template, or evaluation framework.
- Give a talk, workshop, or detailed recorded walkthrough.
- Curate a definitive resource path and keep it reviewed.

**Proof:** series, repository adoption, talk, peer feedback, and updated resource collection.

## Recommended public skill taxonomy

Keep the public list small and outcome-oriented:

- **AI Systems:** LLM pipelines, structured extraction, evaluation, RAG, inference reliability.
- **Machine Learning:** forecasting, classification, uncertainty, experimentation, error analysis.
- **Production Engineering:** Python, FastAPI, Ray, data pipelines, observability, CI/CD.
- **Decision Systems:** simulation, optimization, reinforcement learning, business metrics.
- **Communication:** architecture diagrams, technical writing, documentation, teaching.

Technologies belong inside case studies where their purpose is clear. Do not lead with a wall of logos.

## Weekly practice loop

- **Build:** one technically meaningful increment.
- **Measure:** one benchmark, evaluation, or failure analysis.
- **Explain:** one diagram or 300–600 word field note.
- **Curate:** annotate one resource with context and takeaways.
- **Review:** remove one weak claim or improve its evidence.

## Quality rubric for published proof

Score each artifact from 0–2 on:

1. Problem clarity.
2. Personal ownership.
3. Technical depth.
4. Decision quality.
5. Evidence and reproducibility.
6. Limitations and honesty.
7. Visual explanation.
8. Reader usefulness.

Publish flagship work only at 13/16 or higher. Anything weaker becomes an experiment or draft, not a featured case study.
